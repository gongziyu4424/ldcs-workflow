## 一、分层原则（方案 §2.1 / §3）

1. **识别 vs 判定分层**：意图 / 槽位走模型；配额、门槛、户籍分类、必含事实是程序硬判定。**排查先分层**——先确定是模型层还是程序层，再动。
2. **能程序兜底就别只指望模型**（如 `retire_calc.category_from_text` 原话扫描；性别未知不猜）。
   词表**三处同步**：`retire_calc` / 抽取提示词 / `llm.py` mock。
3. **业务口径只沉淀在「程序 + 单测」里**，提示词与流程都不写规则。
4. **模型能判的语义绝不用正则硬匹配**（公子宇：「你不要硬匹配」）。
   模型输出编码（`reason_code` 7 码 + `REASON_CODE_HINTS`），程序只做白名单 + 词表兜底；
   正则只当第二道保险，且要覆盖夹字：`(工厂|厂里|单位|公司|车间)[^，。；、！？]{0,4}裁`。

## 二、话术层：软提示 + 硬闸门（方案 §4.7）

5. **兜底稿 `fallback_text` 不许透给模型**；提示词别写可照抄的句式 / 菜单名 / 路径 / 示例。
   **硬闸门是 `forbidden_facts`**（`fact_violation()` 命中整段换 fallback）——提示词说"不许说什么"是**软**的，禁语表才是**硬**的。
6. **`required_facts` 宁少勿多 + 同义容差**（`_SYNONYM_FACTS` key 不许重名 / `_LOOSE_FACT_PATTERNS`）——
   设多了会把兜底段**追加**上去 = 同一句话说两遍。
7. **话术短、说人话**：反问 ≤35 字、结论 3~4 句；**禁「已记下」套话**；
   绝不许声称记下用户没说过的（hint 注入 `{known}`）。
8. **内部提示别照抄进回复** —— 既喂模型又上界面的字符串，一律拆**长 / 短两版**（`ASK_TOPIC` / `ASK_TOPIC_SHORT`）。
9. **hint 不许写「节奏描述 / 范文」**；开场只问候一句，**不介绍本工具能做什么**。
10. **一个 action 多套话术 → scaffold 里逐套钉死 `hint_key`**
    （失业金合格 / 不合格 / 只差登记共用 `conclusion_unemp`，曾自相矛盾）；专测 `check_unemp_conclusion_hint()` 三分支。
11. **指引话术必须点名「用户正在问的那件事」**，禁「这项业务」（`_GUIDE_SS_FORBIDDEN`）；
    `flow._service_name()` 三级判定，动词跟业务走（申领 / 办理 / 查询）。
12. 并列条件**合并同义项**。带单位字段用 `{xxx_cn}`（只许照搬、不许再补字，否则「满 15年 年」）。

## 三、追问与配额（方案 §4.6）

13. 只问**真正缺的那一项**。
14. 「不记得了」只作废被问的那一项，**不停整条支线**。
15. **配额只被「答非所问」消耗**（`*_progress` / `*_in_context` 为真即归零；`_CTX_FIELDS` 前置短路）。
16. **「本业务字段」绝不判答非所问**（`_SELF_INFO_CUE` 命中先跨支线抽一遍）。
17. 用户反问 = **范围内正面解答**。
18. 「答不上来」→ `retry_kind="unknown"` → 换 `ask_unknown_guide`
    （**每个 `check_*` 都要写 `retry_kind`**）；**不新增节点**。

19. **业务诉求永远优先于办理指引** —— `query` 是**兜底**（垫底）。

## 五、改口纠正（方案 §4.8）

22. 四件套：抽取 `corrections` → `_apply_corrections` 覆盖写回 → `fix_route` 回支线 → `check_*` 加 `ask` 出口。
23. **四个洞**：
    - **路由**：改口后没回到正确支线
    - **误抽**：`_extract_retire_rule` 见 4 位年份当出生年 → 护栏 `_insured_year_misread()`
    - **重算**：要**比对本轮前后快照**；`birth_year` ↔ `retire_birth_year` 双向同步
    - **路由过度**：把普通补充也判成更正
24. **排查口诀**：`state 变没变 → 派生重算没 → 回对支线没 → 结论重新播报没`。
25. **兜底必须自己会算** —— 真模型偶尔漏抽 → 落到程序正则 → **间歇性**错误，最难排查。
    手法：先分层（模型 vs 兜底），再打**线上**复现。

## 六、话题机制（方案 §4.10）

26. **每次抽取都要把「当前在问什么」显式交给模型**（抽取器**单轮无历史**）；
    `strip_topic_prefix()` **必须幂等**；落档只存短版。
    ⚠️ `extract_gender_age_system` 的 schema **没有顶层 province/city** → 户籍只能走 `corrections`，
    「我户籍是江西九江的」（首次给）留空是**正确**的，别当 bug。
27. **话题只是「优先关注点」，不是围栏**（三层：`【字段归属】` 每轮注入 + 无话题也占位 / extract 口径「先校准再按词面」/ `_gd_years_from_text` 兜底）
    —— 「说错」二字不足以构成改户籍的理由。
28. **「数字 + 单位」先问是「量」还是「标」**（缴了 16 年 = 时长 / 从 16 年到现在 = 年份 / 省内 16 年 = 年限）。
29. 结论后纯致谢 → 一句话收尾。
    ⚠️ 2026-09-14 线上实测「好的谢谢」仍回申领指引，公子宇决定**先不改**。

### 补充：年龄抽取的死锁（2026-09-17 已修，易复发）

**现象**：「江西人 → 女，25」必定重复追问年龄。
**根因**：兜底采纳要求 `attempt_gender_age ≥ 1`，而"用户在正常回答"这条规则会**把该计数归零** —— 门槛永远够不着，兜底形同不存在。
**改法**：门槛改为「`stage == await_gender_age`（正在问这一项）」即采纳；加护栏：原话含「现在 / 今年 / 目前」**不**采纳（那确实是当前年龄）。
mock 正则同步补「性别 + 裸数字」（`女，25` / `女25` / `女的，25`），并排除「交了 20 年」「58 年生的」。
**教训**：**两个规则各自看都对，凑一起互相抵消** —— 这种 bug 只能靠"单输入多写法"的对照矩阵测出来，单测全绿不代表真机对。

    分片多时用「带唯一性断言的补丁脚本」：每处 `s.count(old) != 1` 立即中止，整体不落盘。

    只改单个字段时可精准替换该字段并备份（曾把 `extract_gender_age_system` 4301 → 4623 字符，其余字节不动）。
32. server **别 nohup**，用 run_in_background。
33. **部署参数**：language=python、port=3000、installCmd=`pip install -r requirements.txt`、startCmd=`python server.py`、
    appName=养老待遇领取地测算、`userAskedToPublish=true`，**必须再加 `createNewApp=true` + `domainPrefix`**。
    - 不显式新建 → 卡「应用预留域名未绑定到本次发布环境」中止（2026-09-17 连报 4 次）

    - ⚠️ `cloudstudio-deploy-history/*.json` 的 `sandboxId`（形如 `15ee1d00…`）**不是 domainPrefix**，别拿它填。
    - ⚠️ **报错 ≠ 没上传**：有一次报错其实已推上去，只是没返回链接 → 报错后**回读线上指纹**

## 八、业务口径

34. **最低缴费年限动态规则** `retire_calc.min_contribution_for(y, m)`：
    2029-12 及以前 15 年；2030 = 15 年 6 个月；2031 = 16 年；…；2039 = 20 年（封顶）；2030 起每跨一整年 +6 个月。
    单测预期值**用同一函数算**，不写死——写死会在跨年时集体失效。

35. **失业金口径分两层**（`unemp_calc.py`）：

    **① 资格** `judge_unemp_eligibility(paid, reason_code, registered, min_wage)`
    四项：累计缴费 ≥12 个月 / 非本人意愿失业（7 码）/ 已办失业登记 / 材料齐全（③④ 经办核验，流程不问）。
    返回**必须分层** `{qualified, eligible, blocked, pending, checks, failed, fail_cn, advice_cn}`。
    ⚠️ **「可补救的手续」≠「资格不符」**：只差办登记时回「符合条件 + 能领多少 + 提醒去办登记」，
    **绝不说"不符合"**（`conclusion_unemp_pending` 挂进 `forbidden_facts`）。

    **② 金额** `calc_unemp_benefit(paid_months, min_wage)`
    <12 不合格；12-48 每满 **12** 个月 = 1 个月；≥48 每满 **6** 个月 = 1 个月；封顶 24；
    金额 = 月数 × 2680 × 90%（向下取整）。`calc_unemp()` 先判资格（**pending 也显示金额**）。

    **③ 缴费时长原话兜底必须认得「起止式」**
    `range_months_from_text(text, now_year=None)`：`年数 = 结束年 − 起始年`，
    「到现在 / 至今」的结束年取**当前年 − 1**（2016→9、2010→15）。
    `paid_months_from_text` **先试起止式**再走 `(\d+)年`。
    ⚠️「缴了 12 年，一直没断过」也像 → 要求「从 / 自」开头**或**四位年份。
    `now_year` 做成参数，单测固定防漂移。

36. **能反推的字段一并记下** —— 参保年份 + 参保年龄 → 出生年份（`birth_year_calc=True`，话术标「推算」）。
37. **退休结论顺序：原在前、延迟在后**。
